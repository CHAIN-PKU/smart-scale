# chengzhong —— 智能电子秤 称重固件

STM32F107VC + HAL，只干一件事：**把重量称准，按协议从串口报给电脑**。
认商品、查单价、算钱，都是电脑那边做的，这里不管。

---

## 一、先看这里：只有 4 个地方需要你改

全部集中在 `Core/Inc/config.h`：

1. **HX711 接在哪个引脚**（默认 PB10 / PB11）
2. **传感器量程**（5kg 填 `5000.0f`，10kg 填 `10000.0f`）
3. **标定系数**（拿已知重量的东西实测出来，方法见第五节）
4. **去皮按键接在哪个引脚**（现在用的是 **PA1**；按下是拉低还是拉高，也在同一个地方改）

改完编译一次就行，其它文件不用动。

---

## 二、接线

### HX711 → 开发板

| HX711 上的丝印 | 接到开发板 |
|---|---|
| VCC / VDD | 3.3V |
| GND | GND |
| DT / DOUT | **PB10** |
| SCK / PD_SCK | **PB11** |

传感器那四根线（E+ / E- / A+ / A-）按 HX711 模块上的丝印接，别接反。

> 供电先说 3.3V 最保险。如果读数幅度太小、称不出小东西，再把 VCC 改接 5V
> （不少教程都这么用），但**先按 3.3V 试**。

### 去皮按键（板子上的 K1）→ 开发板

本地手动去皮用。电脑发 `tare` 命令照样能去皮，两条路并存，互不影响。

| 按键 K1 | 接到开发板 |
|---|---|
| 一端 | **GND** |
| 另一端 | **PA1** |

按下时该脚被拉到地，固件里开了内部上拉，所以不用外接上拉电阻。

> 换别的脚也行，改 `config.h` 里 `TARE_KEY_PORT` / `TARE_KEY_PIN` 两行即可
> （注意别和 PA9/PA10 的串口、PB10/PB11 的 HX711 撞）。
>
> 如果按下去没反应，还有个可能：你的板子是**按下拉高**。把 `TARE_KEY_ACTIVE_LOW`
> 改成 `0` 就行。

### 串口 → 电脑

| 开发板 | 接到 |
|---|---|
| PA9 (USART1_TX) | USB 转串口的 RX |
| PA10 (USART1_RX) | USB 转串口的 TX |
| GND | USB 转串口的 GND（**一定要共地**） |

串口参数：**115200，8 数据位，无校验，1 停止位**。

> 如果你的板子插上 USB 就自带一个 COM 口，那它一般就是接在 PA9/PA10 上的，直接用。
> 便宜的那种 ST-Link V2 小 U 盘**不带**虚拟串口，别指望它出 COM 口。

### ST-Link V2 → 开发板（下载和调试用）

| ST-Link V2 | 开发板 |
|---|---|
| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND |
| 3.3V | 3.3V（板子自己有供电的话可以不接） |

Keil 工程里**已经配好 ST-Link Debugger + SWD**，不用再选。

## 三、编译和下载

1. 双击 `chengzhong.uvprojx` 用 Keil 打开
2. 按 `F7` 编译（应该 0 错误 0 警告）
3. 按 `F8` 下载（或者点 Debug 按钮进调试）

生成的 `Objects\chengzhong.hex` 也可以直接用 ST-Link Utility 之类的工具烧。

> 打不开工程 / 找不到器件，说明 Keil 里没装 **Keil.STM32F1xx_DFP** 器件包，
> 用 Pack Installer 装一下就好。

## 四、先跑起来看一眼（还没标定也能做）

烧进去以后打开串口助手，你应该马上看到这两行：

```json
{"v":1,"type":"status","seq":1,"timestamp_ms":12,"state":"BOOT"}
{"v":1,"type":"status","seq":2,"timestamp_ms":15,"state":"READY"}
```

看到 `BOOT` 和 `READY`，说明**串口这条线通了**，第一步就成了。

接着把东西放到秤上、再拿走，你会看到一串 `weight` 和 `status`。
这时候数字肯定不准（还没标定），但**状态跳变是对的**就说明程序在正常跑。

---

## 五、标定（最关键的一步）

标定就是：告诉程序「空秤时读数是几」和「每 1 克对应多少个读数」。

**第 1 步**：把 `config.h` 里的 `DEBUG_PRINT_RAW` 改成 `1`，编译下载。

现在每采一次样，串口助手会多打一行（前面带 `#`，不是 JSON，电脑会自动忽略）：

```
# RAW=8412345 g=0.0
```

**第 2 步**：秤上什么都不放，等读数稳定，记下这个 RAW 值（比如 `8412345`）。

**第 3 步**：放一个你知道重量的东西上去，比如 200g 砝码，等稳定，记下 RAW 值（比如 `8523456`）。

**第 4 步**：算一下每克多少读数：

```
每克读数 = (8523456 - 8412345) / 200 = 55.555
```

**第 5 步**：把这两个数填回 `config.h`：

```c
#define CALIB_ZERO_RAW        8412345L
#define CALIB_COUNTS_PER_G    55.555f
```

顺手把 `DEBUG_PRINT_RAW` 改回 `0`。

**第 6 步**：重新编译下载，放上 200g 砝码，串口上应该显示 `"weight_g":200.0` 左右。
误差在 1 克以内就够用了。

> 标定用的重量越大越准（别用几十克的小东西标 5kg 的量程）。
> 换传感器、换 HX711 模块、动过接线，都要重新标。

## 六、协议：你发出去的三行

三行共用一个 `seq`，**每发一条加 1**。`timestamp_ms` 是从上电开始数的毫秒。
一行用换行结束，**不超过 512 字节**。

### 1. 重量（每来一个新样本发一条）

```json
{"v":1,"type":"weight","seq":182,"timestamp_ms":192839,"weight_g":326.4,"stable":true,"tare_g":12.7,"status":"ok"}
```

- `weight_g`：**已经减掉零点之后的净重**，单位克
- `tare_g`：当前减掉的皮重
- `stable`：这次算不算稳住了

### 2. 状态（状态变了才发，没变不重复发）

```json
{"v":1,"type":"status","seq":2,"timestamp_ms":40,"state":"WEIGHT_STABLE"}
```

`state` 只可能是这八个词：

| 状态 | 什么时候 |
|---|---|
| `BOOT` | 刚上电 |
| `READY` | 初始化完成 |
| `ZERO` | 空秤、净重不超过 2 克、已经稳住 |
| `WEIGHT_CHANGED` | 放上去还在动 |
| `WEIGHT_STABLE` | 连续约 0.5 秒、波动 ≤ 0.5 克 |
| `WEIGHT_REMOVED` | 东西刚拿走，只报一次 |
| `OVERLOAD` | 超过满量程的 90% |
| `ERROR` | 1 秒读不到传感器数据 |

### 3. 去皮应答

```json
{"v":1,"type":"ack","seq":183,"timestamp_ms":193100,"command":"tare","status":"ok"}
```

## 七、协议：你会收到的两行

### 去皮命令

```json
{"v":1,"type":"command","command":"tare"}
```

收到就去皮：连续取 **10 个新样本求平均**当成新零点，回一条 `ok`，然后进 `ZERO`。

**只有这四种情况下才去皮**：空秤、重量在变、已经放稳、刚拿走。

**上电、过载、故障的时候收到去皮，回 `error`，而且原来的零点一点不动。**

### 价格（电脑算完发过来的）

```json
{"v":1,"type":"display_result","request_id":"r_001","product":"banana","weight_g":326.4,"price":3.92}
```

程序会把它记下来，同时在串口上打一行给人看的：

```
# DISPLAY product=banana weight_g=326.4 price=3.92
```

以后接屏幕，数据已经从 `Proto_GetDisplayProduct()` / `Proto_GetDisplayWeightG()` /
`Proto_GetDisplayPrice()` 这三个函数里取就行，不用改协议。

## 八、自测清单（照着文档一条条过）

- [ ] 上电先看到 `BOOT`，再看到 `READY`
- [ ] 空秤稳住以后状态是 `ZERO`
- [ ] 放东西：先 `WEIGHT_CHANGED`，再 `WEIGHT_STABLE`
- [ ] 拿走：出现**一次** `WEIGHT_REMOVED`，然后回到 `ZERO`
- [ ] 空秤一直放着，不会反复报"拿走"
- [ ] **上电时秤上放着东西，开头报的是真实重量，不会被清成 0**
- [ ] 过载或者没接传感器的时候发去皮，回的是 `error`
- [ ] 串口里夹一行乱码或者超长的行，后面的正常数据还照样出

## 十、出问题先看这里

| 现象 | 先查什么 |
|---|---|
| 串口一个字都没有 | 波特率是不是 115200 8N1；TX/RX 有没有接反；有没有共地 |
| 一直停在 `ERROR` | DT 那根线接好没有；HX711 有没有供电；先用 `DEBUG_PRINT_RAW` 看有没有 RAW 输出 |
| RAW 一直是 0 或者一直不变 | DT 和 SCK 接反了（接反不会烧，但读不到数） |
| 数字乱跳 | 电源和地线接好；传感器那四根线有没有虚焊 |
| 上电就报 `OVERLOAD` | `SCALE_FULL_SCALE_G` 填错了，或者没标定 |
| 重量是负的 | A+ / A- 接反了，或者标定的时候零点记错了 |
| Keil 里下载失败 | ST-Link 驱动装了吗；SWDIO/SWCLK 有没有接反；板子有没有供电 |

## 十二、几个说明

**主频**：默认用芯片内部 HSI，36MHz，不依赖外部晶振，什么板子都能先跑起来。
板子上确实有 8MHz 晶振的话，把 `config.h` 里的 `USE_HSE_8M_CLOCK` 改成 `1` 就是 72MHz。

**上电不做自动去皮**，这是文档明确要求的。零点只来自你的标定常数。

**读数不会卡死**：等 HX711 的每一步都有超时，1 秒等不到就进 `ERROR`，
后面的正常数据还能继续发出去。

**调试打印不会污染协议**：所有给人看的行都以 `#` 开头，不是 JSON，电脑会自动丢掉。
